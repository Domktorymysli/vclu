### Home Assistant / MQTT

- Contract change: **only exposed objects are on MQTT** - MQTT now carries only exposed objects, under `vclu/exposed/...`; the per-object registry topics `vclu/<clu>/<component>/<object>/...` (`state`, `set`, `brightness`, `position`, `tilt`) are removed. Objects from the Object Manager import are exposed at start as before (`exposeRegistry()`), so their Home Assistant entities, which discovery has always pointed at `vclu/exposed/...`, keep working. A Grenton thermostat from the import is not exposed by itself: give it `expose(th, "climate", ...)`. A Node-RED flow or a hand-written YAML on the old topics moves to `vclu/exposed/vclu/<component>/<clu>_<object>/...` (lowercase, e.g. `vclu/exposed/vclu/switch/clu220000592_dou0789/set`). Old retained values stay on the broker until cleared: `mosquitto_sub -h <broker> -t 'vclu/+/+/+/state' -t 'vclu/+/light/+/brightness' -t 'vclu/+/cover/+/position' -t 'vclu/+/cover/+/tilt' --remove-retained -W 2`. The undocumented `MqttHandler` class and the unused Go discovery generator (`omparser.GenerateHADiscovery`) are removed with them.
- **`expose(..., { mqtt = false })` takes the object off MQTT entirely**: no discovery, no state, no commands.
