### Plugins

- **Plugin wizard (prototype)** - a plugin declares its configuration in a form file (`"form": "form.json"` in `plugin.json`) and the plugins page opens it as a wizard in three steps. Settings: text, numbers with a range and unit, yes/no, a choice, an IP address, secrets, and fields shown only for a value of another. Devices: a list the plugin can fill with `plugin:discover`; a new discovery keeps what the user changed and marks what is new. Code: `plugin:moduleCode` proposes Lua for the saved devices, the page shows the diff, and vclu writes it to `modules/plugins/` and reloads only after the user confirms, and not over a module edited after the diff was shown. Two plugins whose wizards would write the same module file (`@a/b.c` and `@a/b_c`) are not installed together, and a wizard does not write over another plugin's module. vclu checks the values on save. A secret (a token, a password) is kept apart from the plugin's settings, the page only shows that it is set, and the plugin reads it with `plugin:secret(name)`; its value shows as `***` in what the plugin logs and in its errors. Form values are one line, without control characters. Addresses from the form are added to the plugin's allowed hosts when the user limited them. Uninstalling the plugin keeps its module and comments out its line in `modules/plugins/init.lua`; installing the plugin again (with the module still on disk) or running its wizard turns it back on, and Lua reloads after uninstalling. Plugins with the older `config` map get the same wizard with one step ([#247](https://github.com/Domktorymysli/vclu/issues/247)).
