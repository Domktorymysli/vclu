### Dashboards

- **Weather forecast tile** - `section:forecast(id, label, src, opts)` shows the next days (the weekday in the page's language, an icon, max/min, the rain in mm and its chance when there is some) and under them the next hours as a temperature line over rain bars. `src` is the Weather plugin (`Plugin.getPlugin("@vclu/weather")`, recognised by its `getForecast`; the forecast needs weather with `getForecast`, [vclu-plugins#16](https://github.com/Domktorymysli/vclu-plugins/pull/16)) or any function returning `{ days = { { date, iconName or icon, min, max, rain, pop } }, hours = { { at, temp, rain } } }`. Days before today in the house's time zone are dropped, the hours run from the current one; temperatures and rain are rounded to one decimal and the chance becomes a whole percent; an icon that is not a Bootstrap icon name shows a cloud. `nil` (the plugin before its first fetch) shows "brak prognozy" / "no forecast", an error in `src` the error mark. `opts`: `days` (1-7, default 5), `hours` (0-48, default 24, 0 hides the chart), `unit` (default `°C`), `icon`, `disabled`, `span`, `size`, `color`; wrong arguments fail at the module's line with `section:forecast(...)` in the message. Two columns wide on a desktop, full width on a phone. Contract: `pkg/lua/dashboard_forecast_test.go` ([#96](https://github.com/Domktorymysli/vclu/issues/96)).

### Plugins

- **`datetime` in the plugin sandbox** - plugins get `datetime.now`, `format`, `fromTimestamp`, `parse`, `diff`, `add`, `between` and `timezone` in the house's time zone (summer time included); `setTimezone` is not given to plugins. With it the Weather plugin ([vclu-plugins#16](https://github.com/Domktorymysli/vclu-plugins/pull/16)) groups its forecast into days in the house's time zone instead of the city's fixed UTC offset from OpenWeatherMap, which missed a DST change. Contract: `TestPluginSandboxDatetime` in `pkg/lua/lua_plugin_test.go` ([#96](https://github.com/Domktorymysli/vclu/issues/96)).
