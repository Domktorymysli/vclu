### Dashboards

- **Thermostat widget** - `section:thermostat(id, label, icon, fns, opts)` (and `dash:thermostat`) shows the current temperature large and the target between `-` and `+`. `fns = { getCurrent, getTarget, setTarget?, getState?, getMode? }`, or a Grenton thermostat (`RemoteThermostat`: `getValue`, `getTarget`, `setSetpoint`, state and mode). Both temperatures show "--" until the first report, never 0. Each tap moves the target by `step` within `min`..`max`; `setTarget` is called once, 1 s after the last tap, and the chosen value stays on the tile until the thermostat reports another target, at most 90 s (as `Panel.HOLD_S` in `lib/panel`). Without `setTarget` or with `readonly = true` the tile has no buttons and the action endpoint refuses a set; it also refuses a value that is not a number or is outside `min`..`max`. With `getMode` the target is written only in manual mode (0), as the Smart Panel's `menu:thermostat`: on holiday, schedule or heat-up the buttons go, the state line says the mode and the endpoint refuses. `opts`: `min` (5), `max` (35), `step` (0.5), `unit` ("°C"), `readonly`, `disabled`, `span`, `size`, `color`; wrong arguments fail at the module's line with `section:thermostat(...)` in the message. Full width on a phone, 56 px buttons. Contract: `pkg/lua/dashboard_thermostat_test.go` ([#64](https://github.com/Domktorymysli/vclu/issues/64)).

- Contract change: **thermostats in rooms** - `section:area`, `section:room` and `dash:floor` accept the kind `climate`: a thermostat exposed with `expose(th, 'climate', { area = ... })` gets the thermostat widget, with `min`/`max` of the expose options (default 5-35); a `readonly` expose disables it. It is not among the default kinds (like switch and lock), so existing dashboards do not change unless the thermostat was exposed with `dashboard = true`, which used to log "has no widget" and now shows it. A `climate` that is not a thermostat (no `getTarget`/`setSetpoint`) still gets no widget. `pkg/lua/dashboard_area_test.go` and `dashboard_room_test.go` now use `fan` as the kind without a widget ([#64](https://github.com/Domktorymysli/vclu/issues/64)).

- **Picking a colour on a dashboard works** - the page sends the colour widget's `setColor` as `{r, g, b}`, and the action endpoint passed only booleans, numbers and strings to Lua, so the colour arrived as `nil` and every pick answered "Value must be {r, g, b}". A JSON object of those values now reaches Lua as a table (found while testing #64).
