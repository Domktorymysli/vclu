### MCP

- **Contract change: MCP tools answer with what the agent needs** - `vclu_logs` without `level` leaves out DEBUG lines and returns 50 entries (was 100, every level); pass `level: "debug"` to see a module's `Logger:debug`. Identical lines in a row come as one entry with `repeated`. `vclu_dashboards` without arguments lists `id`, `name`, `auth` and `widgetCount`; pass `id` for that dashboard's widgets (a room tile, not its room's widgets). Every tool now refuses an argument it does not know, and a missing required one, instead of ignoring it, and names the valid ones (`unknown argument "search" for vclu_logs; did you mean "filter"?`); a number may come as a string (`"10"`), any other value for a number is an error. New: `vclu_draft_edit` changes a draft, or the production module when there is no draft, by replacing an exact string and answers with the size, not the file; `vclu_read_file` takes `offset`/`limit` in lines and then gives `total_lines`; `vclu_draft_test` leaves the runtime's start-up lines out of `logs` (`verbose: true` brings them back) ([#120](https://github.com/Domktorymysli/vclu/issues/120)).
