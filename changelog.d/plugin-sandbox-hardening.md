### Plugins

- **Contract change: plugin permissions** - `plugin.json` declares what a plugin reaches beyond HTTP to the internet: `"permissions": {"lan": true, "mqtt": true, "modbus": true}`. `lan` allows HTTP to local addresses (checked after DNS resolution), `mqtt` the plugin's MQTT methods, `modbus` the `Modbus` table. A plugin without the field gets none of them; an official plugin (from the official repository, or installed by hand in `@vclu`) keeps all three, with a warning in the log, until its manifest declares them.
- **Contract change: a stricter sandbox** - a plugin gets its own copies of `string`, `table` and `math`; `Logger`, `JSON` and `Plugin` cannot be modified, and the `HTTP`, `HttpClient` and `MQTT` globals are gone (use `plugin:httpRequest`, `plugin:mqttSubscribe`). Objects a plugin did not create, other plugins included, are read-only also through `pairs`: only `get`, `getX`, `isX` and `hasX` methods can be called on them, and another plugin shows only its sensors and controls. `Plugin.getPlugin` returns the plugin's own instance; its id cannot be changed. Event payloads reach a plugin read-only, a plugin clears only its own timers, an `expose` path goes under the plugin's id, and a disabled plugin's pollers, HTTP retries and exposed objects go away with it. Events a plugin emits start with its prefix: an official plugin's short id or its first word (`sun:`), any other plugin's full id (`@jan/foo:changed`). `Plugin.getPlugin` by short id prefers the `@vclu` plugin and refuses an ambiguous name. No official plugin is affected.
- **Read-only data in the standard library** - an event payload or a registry object a plugin reads works as before with `JSON:encode`, `plugin:encodeJson`, `table.concat` and `unpack`, and is passed on whole by `plugin:emit` and `plugin:mqttPublish`; `table.insert`, `table.remove` and `table.sort` on it are refused.
- **Contract change: plugin ids are lower case** - a namespace and a short id use `a-z`, digits, `.`, `_` and `-`, without `--` or a `-` at either end, so two ids never share a directory or KV file. An exposed path of a plugin that would share an MQTT topic with another path is refused; a plugin cannot change an object a module exposed. A plugin without `lan` is also refused this machine's own networks, global IPv6 included.
- **A Grenton object's index is an integer** - `get`, `set` and `execute` on a CLU object refuse an index that is not one, instead of building it into the code sent to the CLU.
- **An update records its repository** - updating an installed plugin from another repository stores that repository, which the plugin's permissions depend on.
- **`plugin:mqttPublish` works** - it passed `retain` and `qos` in the wrong order and failed on every call.
