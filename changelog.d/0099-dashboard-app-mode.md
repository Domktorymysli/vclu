### Dashboards

- **Full width and app mode on wall tablets** - `Dashboard.new(id):width('full')` (also on a section handle) lets the sections fill the screen edge to edge with an 8 px gutter instead of the centred 1100 px column; `'normal'` is the default, `:columns(n)` still sets the columns and `modules/custom.css` still wins. The definition carries `width` only when a module sets it; a value other than `'full'` or `'normal'` fails at the module's line with `:width()` in the message. Every dashboard page (and its PIN page) now has the home-screen meta tags, an icon and a manifest at `/d/<id>/manifest.webmanifest` (`display: standalone`, `fullscreen` with `width('full')`, theme colour from `:theme({background=...})`, else the default dark background). The manifest needs no PIN or login, since browsers fetch it without cookies, and holds only the dashboard's name and theme colour. To put a dashboard on the home screen: on an iPad open it in Safari → Share → Add to Home Screen; on Android open it in Chrome → menu → Add to Home screen (or Install app). It then opens without browser bars; a PIN or session dashboard asks once more inside the app, which keeps its own cookies. The page uses `viewport-fit=cover` with safe-area paddings, so tiles stay clear of a notch and the home indicator. In a browser that supports the Fullscreen API (Android, desktop) and outside a home-screen app, the header has a full-screen button; not on iPhone and iPad. Contract: `pkg/lua/dashboard_width_test.go`, `pkg/web/dashboard_app_test.go` ([#99](https://github.com/Domktorymysli/vclu/issues/99)).
