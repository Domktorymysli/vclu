### Dashboards

- **Full width and app mode on wall tablets** - `Dashboard.new(id):width('full')` (also on a section handle) lets the sections fill the screen edge to edge with an 8 px gutter instead of the centred 1100 px column; `'normal'` is the default, `:columns(n)` still sets the columns and `modules/custom.css` still wins. The definition carries `width` only when a module sets it; a value other than `'full'` or `'normal'` fails at the module's line with `:width()` in the message. Every dashboard page (and its PIN page, drawn in the default dark look) now has the home-screen meta tags, an icon and a manifest at `/d/<id>/manifest.webmanifest` (`display: standalone`, `fullscreen` with `width('full')`, theme colour from `:theme({background=...})`, else the default dark background; a light background gets the dark-on-light status bar). The app's scope is the whole site, so tabs, chip links to other dashboards and the login page open inside the app. The manifest needs no PIN or login, since browsers fetch it without cookies, and holds only the dashboard's name and theme colour; a `session` dashboard gives its id instead of its name until the user is logged in. To put a dashboard on the home screen: on an iPad open it in Safari → Share → Add to Home Screen; on Android open it in Chrome → menu → Add to Home screen (or Install app). It then opens without browser bars; a PIN or session dashboard asks for the PIN or login once more inside the app (the login page stays in the app), since the app keeps its own cookies. The page uses `viewport-fit=cover` with safe-area paddings, so tiles stay clear of a notch and the home indicator. In a browser that supports the Fullscreen API (Android, desktop) and outside a home-screen app, the header has a full-screen button; not on iPhone and iPad. With `width('full')` a portrait tablet (601-900 px) shows up to 3 columns (`min(columns, 3)`) instead of 2.
