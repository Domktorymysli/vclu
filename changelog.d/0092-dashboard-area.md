### Dashboards

- **A room from the house model** - `section:area('Salon')` fills a section with a widget for every device `expose()` put in that area, picked by kind as `Panel.area` does: a light, switch or lock a toggle, a dimmer a dimmer, an RGB light the colour widget, a cover a cover, temperature and humidity a status (a thermostat none yet, #64). `kinds` (default light, dimmer, cover, temperature, humidity) and `skip = { path }` choose, lights come first, then covers, then the rest by name in Polish order (Ł right after L, case-insensitive), labels are the `expose()` names and a read-only device's widget is disabled. The section is filled each time the dashboard is read, so devices a plugin exposes later show up without a rebuild; widgets added by hand come after the area's. Widget ids are `area:` + the path, the same after a reload (ids starting with `area:` cannot be given by hand). `dash:floor('Parter', { order, titles, kinds, skip })` adds one section per area on that floor (by name, also in Polish order), empty ones left out. `expose(obj, type, { dashboard = false })` keeps an object off dashboards and `dashboard = true` puts it on whatever its kind, separately from `panel`; Home Assistant and HomeKit ignore it. Wrong arguments stop the module with an error naming `section:area` or `dash:floor`, the module's line and what is allowed. `Panel.area` and `Panel.floor` now share the selection with dashboards, unchanged ([#92](https://github.com/Domktorymysli/vclu/issues/92)).
