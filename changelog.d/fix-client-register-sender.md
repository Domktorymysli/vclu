### Grenton

- **Clients registered on vclu get reports after a change** - `SYSTEM:clientRegister` stored the subscription where the reporter did not look, so a client got only the answer with the values at registering and none of the changes after it. Now every registered client, Object Manager included, gets a report after a change, and a session that is not renewed ends after its TTL. A client that registers with address 0 and port 0 gets its reports where it sent the request from, as from a CLU; the same for `clientDestroy(0,0,...)`. A registration with a bad address, a port outside 1-65535 or a bad subscription list is refused, and a broken entry no longer stops the reports of other clients. A text value with quotes, backslashes or new lines is sent escaped (also by `SYSTEM:fetchValues`), so it no longer breaks the reports.
