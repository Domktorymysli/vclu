### Grenton

- **myGrenton interface from the project** - an import of the Object Manager project, or of a diagnostic pack that carries one, also reads the myGrenton interface designed in OM (`nodes/<id>/data.json`) and translates it into vclu's own model of dashboards, kept in `imports/panels/`; a project or pack without one removes it, a single om.lua leaves it alone. Only the translator knows Grenton's format. Every value is checked: CLU and object IDs as in om.lua, scripts and user features as Lua names, indexes as numbers, a script's arguments as numbers and plain strings, and what a widget names is looked up in the project. A scheduler, a widget whose object is not in the project, a command to the CLU itself or a call that fails a check is left out with the reason ([#219](https://github.com/Domktorymysli/vclu/issues/219)).
- **Dashboards tab** - the Grenton page lists the pages of the imported interface with their widgets (what each reads and does) and what was left out; the chosen pages become plain dashboard code in `modules/dashboards/imported/` (one `page_<id>.lua` each, joined as tabs), which is the user's from then on. vclu replaces a file it wrote only after asking, never one the user wrote or changed; it adds `require("dashboards/imported")` to `modules/init.lua` only when asked, and then reloads Lua. Each page loads on its own, so one that fails does not stop the others ([#220](https://github.com/Domktorymysli/vclu/issues/220)).
- **`Wire` helpers** - the reads and commands those files use: `Wire.value`, `feature`, `variable`, `isOn`, `text`, `percent`, `fromPercent`, `set`, `execute`, `script`, `onOff`, `load`. Reads never wait for a CLU: what the registry follows comes from it, the rest is asked in the background and the widget shows the last answer. Reads and commands reach only objects in the registry, through their proxies and their guards; one vclu has no proxy for shows "not imported". A level that is 0-1 in Object Manager (a dimmer, an LED's brightness and saturation) is a 0-100% slider. `CLU_REMOTE:getAsync(name, done)` reads a user feature without blocking ([#219](https://github.com/Domktorymysli/vclu/issues/219)).
