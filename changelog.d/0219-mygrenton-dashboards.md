### Grenton

- **myGrenton interface from the project** - an import of the Object Manager project, or of a diagnostic pack that carries one, also reads the myGrenton interface designed in OM (`nodes/<id>/data.json`) and keeps it in `imports/mygrenton/`; a project or pack without one removes it, a single om.lua leaves it alone. Every value is checked before it reaches Lua: CLU and object IDs as in om.lua, scripts and user features as Lua names, indexes as numbers, a script's arguments as numbers and plain strings. A widget that names an object not in the project, a scheduler, or a call that fails a check is left out with the reason ([#219](https://github.com/Domktorymysli/vclu/issues/219)).
- **`MyGrenton.widget(section, widget)`** - a runtime module that adds a myGrenton widget to a dashboard section: on/off as a toggle, values and texts as statuses, a slider where the interface lets the user enter the value, scenes as buttons, a thermostat with its current and set temperature. Reads never wait for a CLU: what the registry follows comes from it, the rest (other features, user features) is asked in the background and the widget shows the last answer. Commands go through the object proxies. `MyGrenton.describe(widget)` tells what a widget would show, read and do; `CLU_REMOTE:getAsync(name, done)` reads a user feature without blocking ([#219](https://github.com/Domktorymysli/vclu/issues/219)).
- **Dashboards tab** - the Grenton page lists the pages of the imported interface with their widget counts and what was left out; the chosen pages become dashboards in `modules/dashboards/grenton/` (one `page_<id>.lua` each, joined as tabs), which are the user's files from then on. vclu replaces a file it wrote only after asking and never one the user wrote or changed; it adds `require("dashboards/grenton")` to `modules/init.lua` only when asked, and then reloads Lua ([#220](https://github.com/Domktorymysli/vclu/issues/220)).
