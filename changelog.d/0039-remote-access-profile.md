### Security

- **Remote access has its own access profile, closed by default** - a new `remote` integration gets the built-in `no-access` profile (default `hidden`) on a fresh install and when an existing `access_control.yaml` has no `remote` assignment; `full-access` is never assigned to it implicitly. The Access page shows a Remote access column and lets the owner pick its profiles; the API accepts `remote` and refuses unknown integrations. `RemoteAccess.objects()` lists the exposed objects not hidden for `remote` with their level, and `RemoteAccess.command(path, command, value, "user:<login>")` refuses hidden and readonly objects and otherwise calls the object's own method (`switchOn`, `setBrightness`, `setPosition`, ...), recording `origin = "remote"` and the given actor. Profile changes apply without a restart. This adds an integration and an `origin` value; `mqtt`, `homekit` and `mcp` and their defaults do not change ([#39](https://github.com/Domktorymysli/vclu/issues/39)).
