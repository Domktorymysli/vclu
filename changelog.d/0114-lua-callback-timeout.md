### Lua runtime

- **Contract change:** a Lua callback that runs too long is stopped, not the whole runtime. A timer callback, event handler, dashboard action, metric getter or a module while it loads that runs longer than 60 s (an HTTP endpoint handler: 30 s) is stopped, also inside `pcall`, and the rest of vCLU goes on. The time is wall-clock, blocking calls included; a synchronous `HTTP:get` ends with the callback. The log names it: `[RUNTIME] Stopped timer 12 (plugin @vclu/x): ran over the 60s callback time limit`, with the plugin or the module line of an `after`/`every` timer; the misleading `KILLED callback` line is gone. A stopped interval keeps its schedule. Set the limit with `"lua": {"callbackTimeoutSeconds": 60}` in `.vclu.json` (read at start, negative turns it off). Migration: a callback that waits longer than that on purpose has to be split into steps (`after()`, async HTTP) ([#114](https://github.com/Domktorymysli/vclu/issues/114)).
