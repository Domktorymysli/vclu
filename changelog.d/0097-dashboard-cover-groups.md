### Dashboards

- **Cover groups** - `section:covers(id, label, list, opts)` puts several covers on one tile: up, stop, down and a position slider act on each of them, a slat slider (0-90°) shows while a cover reports a tilt (`getTilt`) and calls `setTilt` only on those. `list` is a list of covers (`RemoteCover`, `VirtualCover`) or their paths, `_:byTag(...)`, or a function returning one, read each time, so covers tagged later show up; a path not in the registry is skipped and logged once. The tile's state line counts the covers ("3 otwarte · 1 w ruchu", "wszystkie zamknięte", in English too) and the slider shows their average position. Commands go out one after another 50 ms apart on timers, without holding the run loop (a CLU drops bursts); a new command for the group drops what is left of the previous one, so "up" then "stop" stops them all. `section(name, icon, { covers = true })` shows the counts of the section's cover tiles and groups in its header (each cover once; in the values as `_section_<n>`). `opts`: `icon`, `disabled`, `span`, `size`, `color`; wrong arguments fail at the module's line with `section:covers(...)` in the message. `RemoteCover` commands follow the Grenton documentation and are untested on hardware; the tilt of a `RemoteCover` is not subscribed yet, so a Grenton roller shows no slat slider. Contract: `pkg/lua/dashboard_covers_test.go` ([#97](https://github.com/Domktorymysli/vclu/issues/97)).
