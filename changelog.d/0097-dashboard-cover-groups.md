### Dashboards

- **Cover groups** - `section:covers(id, label, list, opts)` puts several covers on one tile: up, stop, down and a position slider act on each of them, a slat slider (0-90°) shows while a cover reports a tilt (`getTilt`) and calls `setTilt` only on those. `list` is a list of covers (`RemoteCover`, `VirtualCover`) or their paths, `_:byTag(...)`, or a function returning one, read each time, so covers tagged later show up; a path not in the registry is skipped and logged once. The tile's state line counts the covers ("3 otwarte · 1 w ruchu", "wszystkie zamknięte", "1 otwarta · 1 brak odczytu", in English too; a cover with no reading is never counted as closed) and the slider shows their average position. Commands go out one after another 50 ms apart on timers, without holding the run loop (a CLU drops bursts); movement and slats are separate series: a new movement command drops what is left of the previous movement, a new slat command the previous slats, stop ends both, so "up" then "stop" stops them all; a group disabled meanwhile sends nothing more. `section(name, icon, { covers = true })` shows the counts in the section's header (in the values as `_section_<n>`): each cover once within groups, while a `:cover` tile counts on its own. Widget ids starting with `_group_` or `_section_` are now refused. `opts`: `icon`, `disabled`, `span`, `size`, `color`; wrong arguments fail at the module's line with `section:covers(...)` in the message. `RemoteCover` commands follow the Grenton documentation and are untested on hardware; the tilt of a `RemoteCover` is not subscribed yet, so a Grenton roller shows no slat slider. Contract: `pkg/lua/dashboard_covers_test.go` ([#97](https://github.com/Domktorymysli/vclu/issues/97)).
